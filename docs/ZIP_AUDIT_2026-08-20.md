## High-priority findings

- `specs/providers/bdl/nfl.yml` is a placeholder, not the official BDL OpenAPI document. Production must fail closed until the exact official bytes are pinned and hashed.
- The original BDL contract encoded the standard cursor as a string; the official OpenAPI contract defines it as an integer.
- The official advanced schema component names use the `Stats` suffix: `NFLAdvancedPassingStats`, `NFLAdvancedRushingStats`, `NFLAdvancedReceivingStats`.
- Live player props are documented as non-historical and non-paginated even though the example includes cursor-like metadata; follow the prose/parameter contract, store your own snapshots, and tolerate response metadata.
- Opening player props expose a schema inconsistency: `updated_at` is listed as required while `opened_at` is the property. Normalize that only at the provider boundary.
- DFS is optional to the predictive core but part of a complete BDL adapter; its array filters use bracketed form/explode wire names and integer cursors.
- The package architecture is strong: the correct action is overwhelmingly IMPLEMENT rather than DELETE.

**Official contract reviewed:** https://www.balldontlie.io/openapi/nfl.yml

- **IMPLEMENT**: preserve the public interface and blueprint intent; write missing production behavior and activate its tests.
- **REPLACE**: replace with authoritative bytes, not a hand-transcribed substitute.
- **DELETE**: no original project source file is recommended for deletion.
